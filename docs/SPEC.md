# The `.deph` file format, version 1

`*.deph` is a plain-text, line-oriented format with its own grammar. It is not
HTML, not Markdown, not a programming language; it contains no executable
code and is never evaluated. One `.deph` file is the single source of truth
for a repository's dependency health:

* **Hand-authored region** (top): `policy` and `waive` blocks, plus comments.
  Tools MUST preserve this region **byte-for-byte** across rewrites.
* **Generated region** (below the marker): `project`/`dep` blocks. Tools own
  this region and fully regenerate it on every `deph scan`.

A file with only a policy block and no generated region (the output of
`deph init`) is valid. An empty file is valid.

## Lexical structure

* Encoding is UTF-8.
* `//` starts a comment that runs to end of line. Comments may follow a
  statement on the same line.
* Newlines terminate statements. There are no semicolons.
* Strings are double-quoted; `\"` and `\\` are the only escapes.
* A **word** is a maximal run of characters excluding whitespace, `{`, `}`,
  `[`, `]`, `,`, `=`, `<`, `>`, `"`, and comment starts. This deliberately
  admits package names (`@scope/pkg`, `follow-redirects`), versions
  (`1.0.0-beta.1`), SPDX ids (`BSD-3-Clause`), advisory ids
  (`GHSA-hfxv-24rg-xrqf`), and colon-joined tags (`vuln:high:GHSA-…`) as
  single tokens.
* Operators: `>=`, `<=`, `==`, `!=`, `>`, `<`, `->`.

Parsers MUST report syntax errors with file, line, and column
(`repo.deph:4:3`).

## The generated marker

A comment line beginning with

```
// ---- generated by deph scan
```

splits the file. Everything above is the hand-authored region; everything
below is the generated region. The canonical form embeds a timestamp:

```
// ---- generated by deph scan @ 2026-07-27 10:00 UTC — do not edit below ----
```

The text after `@` (up to a trailing dash sequence) is the scan timestamp,
treated as an opaque string. Two consecutive scans over unchanged
dependencies MUST produce identical files except for this line.

## Grammar (EBNF)

```ebnf
file            = header , [ marker , generated ] ;

header          = { header_item } ;
header_item     = policy_block | waive_stmt | comment | blank_line ;

policy_block    = "policy" , "{" , { policy_rule } , "}" ;
policy_rule     = action , subject , constraint , [ scope_clause ] , line_end ;
action          = "fail" | "warn" ;
subject         = "vuln" | "lag" | "license" | "unresolved" | word ;
                  (* an unknown subject is a lint warning, not an error *)
constraint      = comparator , word
                | ( "not" | "in" ) , value_list ;
comparator      = ">=" | "<=" | "==" | "!=" | ">" | "<" ;
scope_clause    = "for" , scope , { "," , scope } ;
scope           = "direct" | "transitive" | "dev" | "prod" ;
value_list      = "[" , value , { "," , value } , "]" ;
value           = word | string ;

waive_stmt      = "waive" , ( word | string ) ,
                  [ "until" , iso_date ] , string , line_end ;
                  (* id, optional expiry, then quoted reason *)
iso_date        = digit4 , "-" , digit2 , "-" , digit2 ;

marker          = "//" , "----" , "generated by deph scan" , … , line_end ;

generated       = { project_block } ;
project_block   = "project" , ( string | word ) , { attr } ,
                  "{" , { dep_stmt | unresolved_stmt } , "}" ;
attr            = word , "=" , value ;

dep_stmt        = "dep" , value , value ,      (* name, resolved version *)
                  { dep_clause } , line_end ;
dep_clause      = "->" , value                 (* latest; only when outdated *)
                | "transitive"
                | "dev"
                | attr                         (* e.g. license=MIT, fix=1.2.3 *)
                | tag_list ;

unresolved_stmt = "unresolved" , value , { attr } , line_end ;
                  (* the requirement text, then reason= and name= *)
tag_list        = "[" , tag , { "," , tag } , "]" ;
tag             = word ;                       (* colon-separated: kind[:q[:id]] *)

comment         = "//" , { any_char_except_newline } ;
line_end        = [ comment ] , newline | EOF ;
```

### Subjects and values

| subject      | constraint forms          | values                                  |
|--------------|---------------------------|-----------------------------------------|
| `vuln`       | comparator + severity     | `low` < `medium` < `high` < `critical`  |
| `lag`        | comparator + lag level    | `prerelease` < `patch` < `minor` < `major` |
| `license`    | `not [allowlist]` / `in [denylist]` | SPDX expressions              |
| `unresolved` | comparator + integer      | a count of unpinnable requirements      |

`prerelease` lag means the resolved version is a prerelease of the same
numeric core as the latest release (`1.0.0-rc.1` behind `1.0.0`). It is
deliberately distinct from `patch`.

An `unresolved` rule fires once per project, comparing against the number of
`unresolved` statements in that project. `warn unresolved >= 1` is the
default, and it exists so a scan that could only read part of a manifest
cannot be mistaken for a clean one.

### Scopes

A rule with no `for` clause applies to every dependency. A `for` clause
narrows it:

```
fail vuln >= high for direct
warn vuln >= high for transitive
fail license not [MIT, Apache-2.0] for prod
```

`direct` and `transitive` split on whether the dependency carries the
`transitive` keyword; `dev` and `prod` split on the `dev` keyword. Multiple
scopes are ANDed, so `for direct, prod` matches only direct production
dependencies. Combining opposites (`for direct, transitive`) can never match
and is a lint warning.

`fail` findings make `deph check` exit 1; `warn` findings are reported but
never fail. GitHub's `moderate` severity is an alias of `medium`. Unknown
severities compare below `low` and match no threshold; they never crash a
parser or evaluator.

### Waivers

```
waive GHSA-xxxx-yyyy-zzzz "vendored code not exposed; upgrade planned Q3"
waive GHSA-aaaa-bbbb-cccc until 2026-09-01 "waiting on upstream release"
```

The id matches a finding's identifier: a GHSA id (or other advisory id) for
vulnerabilities, or the synthetic ids `license:<dep-name>`, `lag:<dep-name>`
and `unresolved:<project>` for the other kinds. Waived findings are reported
as `waived`, never fail a check, and render struck-through with their reason
in studio. Waivers live in the hand-authored region and survive every re-scan.

An `until` date is compared against the current UTC date. Past that date the
waiver stops applying and the finding is reported at its normal level again,
flagged so the output can say the waiver expired rather than looking like a
new problem. A waiver with no date never expires; dates exist because a
permanent waiver is a permanent blind spot.

### Dep lines

```
dep axios 0.21.1 -> 1.18.1 license=MIT fix=0.21.2 [vuln:high:GHSA-hfxv-24rg-xrqf, lag:major]
dep follow-redirects 1.14.0 -> 1.16.0 license=MIT transitive [vuln:medium:GHSA-r4q5-vmmm-2653]
dep jest 27.5.1 -> 29.7.0 license=MIT dev [lag:major]
```

* `-> latest` is present **only** when the resolved version is outdated.
* `transitive` marks indirect dependencies; its absence means direct.
* `dev` marks a dependency that is not shipped: devDependencies,
  `[dev-dependencies]`, a `packages-dev` entry, and so on.
* `license=` values that contain spaces (SPDX expressions) are quoted.
* `fix=` is the lowest version clearing every advisory on the line. When a
  dependency has several advisories it is the highest of their individual
  fixed versions, since a lower one would not clear the rest.
* `cwe=` carries the first CWE id when the advisory source supplies one. CVSS
  vectors are deliberately **not** stored: they are long enough to make every
  dep line unreadable in a diff, the severity is derived from them, and the
  advisory page has them.
* Names and versions are normally bare words; writers MUST quote any value
  that cannot round-trip as a word (spaces, `=`, brackets, `//`, …), and
  parsers MUST accept a quoted string wherever a name or version appears.
* Bracketed tags carry findings: `vuln:<severity>:<advisory-id>`,
  `lag:<level>`, and the bare tags `yanked` and `deprecated`.

### Unresolved lines

```
unresolved "flask>=2.0" reason=range name=flask
unresolved "-e ./local-package" reason=local
unresolved "sibling@workspace:*" reason=workspace name=sibling
```

A requirement the scanner could identify but not pin to one version. The
`spec` is the manifest text as written. `reason` is one of:

| reason      | meaning                                              |
|-------------|------------------------------------------------------|
| `range`     | a version range rather than a pin (`flask>=2.0`)     |
| `unpinned`  | named with no constraint at all                      |
| `vcs`       | a git/hg/svn dependency                              |
| `url`       | a direct URL or remote archive                       |
| `local`     | a path or editable install                           |
| `workspace` | a `workspace:` sibling or in-repo path               |
| `missing`   | an include (`-r`/`-c`) that could not be read        |
| `unparsed`  | syntax the scanner did not recognise                 |

These exist so a scan cannot silently shrink. A `requirements.txt` of six
ranges must not audit as an empty, clean project. Tools MUST record every
requirement they decline to resolve, and SHOULD surface the count.

### Forward compatibility

Parsers MUST ignore (and writers SHOULD preserve where the region is
hand-authored) anything they do not understand:

* unknown `key=value` attributes on `project` and `dep` lines,
* unknown tag kinds inside `[...]`,
* unknown policy subjects (a lint *warning*, not an error).

New constructs in future spec versions will follow these shapes so v1
parsers keep working.

## Versioning

This document describes **v1**. Breaking grammar changes will bump the
version and be announced in the file header convention (`// deph v2 …`).
